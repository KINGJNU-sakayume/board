# Life Board 디자인 규칙

> 보드와 모든 앱 타일이 따르는 하나의 디자인 문서입니다.
> 기준 구현은 이 저장소의 `css/board.css`와 `js/render.js`이고, 값(색, 크기, 숫자)이 이 문서와 충돌하면 코드가 이깁니다.
> 앱이 보낼 데이터 형식은 [TILES.md](TILES.md), 앱별 후보 타일은 [CANDIDATES.md](CANDIDATES.md)에 있습니다.

---

## 0. 한 줄 요약

**화면은 무채색, 색은 콘텐츠(표지·사진)에서만 나온다.**
UI가 색을 가지려 들지 않으므로 앨범·책·애니 표지가 여러 장 들어와도 화면이 시끄러워지지 않습니다.

앱은 **무엇을 보여줄지(데이터)** 만 정하고, **어떻게 보일지(모양)** 는 보드가 정합니다.
앱이 HTML이나 CSS를 보내는 일은 없습니다. 앱은 아래 톤 중 하나를 고르고 그 톤의 칸을 채운 JSON을 보냅니다.

---

## 1. 화면 구조

### 1-1. PC: 화면을 꽉 채우는 가로 스크롤
- 페이지 높이는 화면 높이(`100dvh`)와 같고, 세로 스크롤은 없습니다.
- 타일 격자의 **세로 칸 수(`--rows`)를 화면 높이에 맞춰** 정하고, 칸 크기(`--unit`)를 그 높이에 꼭 맞게 계산합니다(`js/layout.js`).
  - 칸 크기는 **120~170px** 사이로 유지합니다. 그래서 1칸 < 200px, 2칸은 200~499px, 4칸 ≥ 500px이 늘 성립하고, 타일 안 배치(4장)가 이 경계에 기대어 동작합니다.
  - 예: 화면 높이 900px → 5줄 × 약 146px, 1080px → 6줄 × 150px, 640px → 3줄 × 163px.
- 그룹(내 하루, 미디어, 정렬·기록, 장소·일상)은 가로로 이어지고, 그룹 안에서 타일은 **위→아래, 왼쪽→오른쪽 순서로 빈칸 없이** 채워집니다(`grid-auto-flow: column dense`).
- 세로 마우스 휠은 가로 스크롤로 바뀝니다. 오른쪽 끝에는 "더 있다"는 흐림이 있고, 끝에 닿으면 사라집니다.

### 1-2. 휴대폰(폭 640px 이하): 2열 세로 스크롤
- 칸 크기는 화면 폭의 절반입니다(390px 폭에서 약 174px).
- 4칸 폭 타일(`4x1`, `4x2`)은 2칸 폭으로 접힙니다. 타일 안 배치는 실제 크기를 보고 정해지므로 따로 처리할 것이 없습니다.

### 1-3. 크기는 다섯 가지뿐
`1x1` · `2x1` · `2x2` · `4x1` · `4x2` (가로×세로 칸). 4x2보다 큰 크기는 필요해질 때 다시 검토합니다.
- 타일마다 **허용 크기(`sizes`)** 와 처음 크기(`size`)를 앱이 정합니다.
- 허용 크기를 정하는 기준은 **"그 크기에서 정말 쓸모 있는 정보가 남는가"** 입니다. 다섯 가지를 억지로 다 허용하지 않습니다.
- 허용 크기가 하나면 크기 조절 핸들이 나타나지 않습니다.

## 2. 색

### 2-1. 색 예산
- 크롬(배경, 타일 면, 글자, 선, 버튼)은 전부 무채색입니다.
- 채도가 있어도 되는 곳은 **표지 이미지**와, 그 표지에서 뽑은 **작은 포인트색**(진행 막대, 알약 배지)뿐입니다.
- 타일마다 다른 테마색을 주지 않습니다. 앱 정체성은 이름(라벨)과 표지로 드러냅니다.
- 예외는 `--danger` 하나이고, 편집 모드의 "위젯 제거"에만 씁니다.

### 2-2. 포인트색은 표지가 정한다
- 포인트색 = `--c: hsl(var(--h) calc(var(--s)*100%) calc(var(--l)*100%))`.
- 색상(`--h`)과 채도(`--s`)는 타일마다, 명도(`--l`)는 테마가 정합니다(다크 `.64`, 라이트 `.40`). 그래서 표지가 어떤 색이어도 글자 대비가 유지됩니다.
- 앱이 `accent: {h, s}`를 보내면 그것을 씁니다. **앱이 보내는 것을 권장합니다.** 다른 출처 이미지는 CORS(Cross-Origin Resource Sharing, 교차 출처 리소스 공유) 때문에 보드가 직접 색을 뽑지 못하는 경우가 많기 때문입니다.
- `accent`가 없으면 보드가 표지를 캔버스로 샘플링해 보고, 실패하면 무채색(`--s:0`)으로 남습니다.
- `--c`는 `:root`가 아니라 `.w, dialog`에 정의합니다. `:root`에 두면 타일별 `--h/--s`가 먹지 않습니다.

### 2-3. 토큰
```css
/* 다크(기본) */
--stage:#1b1d21; --paper:#262a30; --paper-2:#31363d;
--ink:#f2f1ee; --mute:#a7acb4; --hair:rgba(255,255,255,.15); --danger:#ff7d73; --l:.64;
/* 라이트 (prefers-color-scheme: light) */
--stage:#e9eaec; --paper:#f8f8f7; --paper-2:#ebebea;
--ink:#17181a; --mute:#555961; --hair:rgba(0,0,0,.16); --danger:#c6291f; --l:.40;
```
- 다크/라이트는 시스템 설정을 따릅니다. 토글 버튼을 만들지 않습니다.
- 하드코딩 색은 `hero` 타일처럼 이미지 위에 놓이는 글자에만 씁니다.

### 2-4. 모서리 반경 3단계 (섞지 않는다)
`--r-tile: 18px`(타일) · `--r-cover: 6px`(표지, 타일보다 작아서 "물건"처럼 보임) · `--r-thumb: 4px`(작은 썸네일)

### 2-5. 글꼴
`system-ui, -apple-system, "Apple SD Gothic Neo", "Noto Sans KR", "Malgun Gothic", sans-serif`. 웹폰트를 불러오지 않습니다.

## 3. 톤: 타일은 여섯 가지 중 하나다

| 톤 | 모습 | 언제 쓰나 | 예 |
|---|---|---|---|
| `sleeve` | 표지가 왼쪽에 꽉 차고(앨범 슬리브), 오른쪽은 글자 라벨 | 표지가 있는 "지금 하는 한 가지" | AniMan 정주행 중, 책장 읽는 중 |
| `hero` | 표지가 타일 전체 + 어두운 막(scrim) 위에 큰 글자 | **그룹마다 하나만.** 그 그룹의 중심 | potcast 지금 듣는 앨범 |
| `strip` | 표지 여러 장을 가로로 나열 | "최근 N개"를 훑어볼 때 | 최근 완주, 최근 읽은 책, 최근 먹은 것 |
| `plate` | 표지판·티켓처럼 윤곽선 있는 물건 하나 | 장소·도장·이름표 | 역 도장깨기, 가고 싶은 역 |
| `map` | 무채색 격자 지도. 방문한 칸만 잉크색, 최근 칸에만 윤곽 | 지역 진행 상황 | 켜켜이 지역 방문 |
| `type` | 상자 없이 윗선 하나 + 글자만 | 숫자·목록·한 줄·칸 같은 정보 | 날씨, 시간표, ELO, 업적, 메모 |

### `type`의 네 형태 (`form`)
| 형태 | 핵심 | 예 |
|---|---|---|
| `num` | 큰 숫자 하나(가볍게) + 단위·보조 | 날씨, 받은 제안, 가격, D-day, 진행률 |
| `list` | 순번·시각 + 제목 + 오른쪽 보조 값. 작아지면 위에서부터 잘림 | 시간표, ELO 순위, 이어 볼 차례, 먹고 싶은 것 |
| `line` | 굵은 제목 한 줄 + 작은 보조 한 줄 | 메모, 스포츠, 최근 취득, 최근 승부 |
| `cells` | 칸 채우기 | 트로피 칸, 시리즈 진행 |

- `type`은 상자(배경·테두리)를 쓰지 않습니다. 편집 모드에서만 상자가 생깁니다.
- `sleeve`/`hero`/`strip`/`plate`/`map`은 `paper` 면 위에 놓입니다.
- `hero`는 같은 그룹 안에서 겹치지 않게 합니다. 표지 전면 타일이 셋 나란히 놓이면 시끄러운 사각형이 셋이 됩니다.

## 4. 위계와 글자

- 가장 중요한 한 가지(기온, 제목, 현재 순위)를 크게 하고, 나머지는 `--mute`로 낮춥니다. 선이나 색으로 위계를 만들지 않습니다.
- 숫자는 크고 가볍게(`font-weight:300`, 2x2에서 96px), 제목은 굵게(`800`, `letter-spacing:-.02em`).
- 한글 줄바꿈은 `word-break:keep-all` + `text-wrap:balance`. 숫자는 `tabular-nums`.
- 글자 길이: 라벨·제목은 짧게(라벨 80자, 긴 문장 160자 제한은 TILES.md). 줄바꿈이 필요하면 `\n`을 넣습니다.

## 5. 크기별 배치는 "타일 자신의 크기"로 정한다

- 화면 폭(`@media`)이 아니라 **컨테이너 쿼리**를 씁니다. 타일 하나하나가 `container-type:size`입니다.
- 같은 타일이 `1x1`일 때는 핵심 한 가지만, `2x2`일 때는 부가 정보까지, `4x2`일 때는 두 면을 나란히 보여줍니다.
  - 예: `sleeve`는 1x1 표지만 → 2x1 표지 + 제목·진행 → 2x2 표지 + 라벨 전체 → 4x2 앞면과 목록을 나란히.
- 작아질수록 숨기는 순서: 보조 문장 → 알약·배지 → 부가 목록 → (끝까지 남김) 제목과 핵심 숫자.
- 작은 크기에서 글자를 줄여 억지로 우겨넣지 않습니다. 숨기거나 한 줄로 합칩니다.
- 앱은 크기별로 다른 데이터를 보낼 필요가 없습니다. 가장 큰 크기에서 쓸 데이터를 보내면 보드가 크기에 맞게 덜어냅니다.

## 6. 상시 버튼 금지, 동작은 제스처로

- 화면에 늘 보이는 버튼이 없습니다(칩, 정렬, 편집 버튼 모두 없음).
- 타일을 누르면: 상세(`detail`)가 있으면 상세 창, 없으면 앱 열기(`href`). 설정이 필요한 보드 위젯은 설정 창.
- 그 밖의 동작은 편집 모드나 우클릭 메뉴에 넣습니다. 예외는 `plate`의 룰렛처럼 타일 자체가 하는 일인 경우뿐이고, 그것도 4칸 폭일 때만 보입니다.

## 7. 편집 모드 (iOS 위젯 방식)

### 진입과 나가기
| 방법 | 동작 |
|---|---|
| 타일 길게 누르기(450ms) | 편집 모드. 누른 채 10px 넘게 움직이면 취소 |
| 마우스 우클릭 | 메뉴: 크기 아이콘 + (보드 위젯이면) 위젯 설정 + 보드 편집 + 위젯 제거 |
| `E` 키 | 편집 모드 켜고 끄기. 한글 입력 상태에서도 동작(`e.code`), 입력창·대화상자 안에서는 무시 |
| 포커스한 타일에서 Enter/Space, Shift+F10 | 메뉴 |
| 나가기 | 완료 버튼, Esc, 빈 곳 누르기 |

### 편집 모드의 모습
- 타일이 아주 살짝 흔들립니다(jiggle). `prefers-reduced-motion`이면 멈춥니다.
- 왼쪽 위 `−` 배지(보이는 크기 26px, 누르는 영역 44px) = 제거.
- 오른쪽 아래 두꺼운 모서리 호 = **크기 조절 핸들**. 허용 크기가 둘 이상일 때만 나옵니다.
- 헤더에는 `+`(위젯 추가)와 `완료`만 나옵니다.

### 크기 조절: 핸들을 끄는 동안 타일이 실제로 바뀐다
- 핸들을 끌면 **끄는 도중에 타일 자체가** 가장 가까운 허용 크기로 바뀌고, 주변 타일이 부드럽게 비켜 납니다. 위에는 가능한 크기 칩(`1×1 2×1 2×2 4×1`)이 뜨고 현재 후보가 굵게 표시됩니다.
- 놓으면 그 크기로 저장됩니다. 끄는 중 Esc를 누르면 원래 크기로 돌아갑니다.
- 핸들에 포커스하고 방향키로도 바꿀 수 있습니다.

### 이동 · 제거 · 추가
- 끌어서 순서와 그룹을 바꿉니다(자리 표시 + FLIP(First-Last-Invert-Play, 위치 변화 애니메이션 기법)). 가장자리로 끌면 자동으로 스크롤됩니다.
- 제거하면 되돌리기 토스트가 뜹니다. 제거한 위젯, 그리고 앱이 `default:false`로 보낸 후보 타일은 `+`에서 추가합니다.
- 배치는 지금은 이 브라우저의 `localStorage`(`board.layout.v1`)에 저장합니다. Hub에 배치를 저장해 기기 간에 맞추는 일은 life-hub P7 B3입니다.

### 구현상 주의 (이미 겪은 함정)
- 포인터 down에서 곧바로 `setPointerCapture`를 하면 뒤따르는 click이 페이지로 가서 메뉴가 닫히고 편집 모드가 풀립니다. **실제로 끌기 시작한 뒤에만 캡처합니다.**
- 길게 누르기·끌기·크기 조절이 끝난 직후의 click, 그리고 **누른 채 Esc로 취소한 뒤 손을 뗄 때의 click**은 삼킵니다(`swallow`).
- 끄는 중인 타일은 FLIP 애니메이션에서 뺍니다. 애니메이션 중 위치가 흔들리면 크기 계산이 틀어집니다.

## 8. 접근성 기준

- 누르는 영역은 최소 44px.
- 모든 타일은 키보드로 도달·조작할 수 있습니다(편집 진입, 크기 변경, 이동 메뉴).
- 메뉴는 `role="menu"` / `menuitem` / `menuitemradio`. 크기 변경·제거는 live region으로 읽어 줍니다.
- 면이 바뀌는 타일(sleeve 앞면/목록)은 안 보이는 쪽에 `aria-hidden`을 맞춥니다.
- 색만으로 뜻을 전하지 않습니다(진행 막대 옆에 `7 / 12화`, 증감에 ▲▼).
- 글자는 WCAG(Web Content Accessibility Guidelines, 웹 콘텐츠 접근성 지침) AA 기준(본문 4.5:1)을 넘깁니다. 이미지 위 글자는 scrim으로 대비를 만듭니다.
- 움직임은 `prefers-reduced-motion`을 존중합니다.

## 9. 보안과 데이터

- 앱이 보낸 글자는 항상 `textContent`로 넣습니다. HTML을 해석하지 않습니다.
- 표지 이미지는 허용된 출처(`js/config.js`의 `imageOrigins`)와 `data:image/`만 불러오고, 나머지는 글자 한 칸으로 바꿉니다. 링크(`href`)도 허용된 출처만 받고, 아니면 타일을 거절합니다.
- CSP(Content Security Policy, 콘텐츠 보안 정책)로 스크립트·스타일은 같은 출처만, 이미지·네트워크는 허용 목록만 씁니다. `imageOrigins`를 바꾸면 `index.html`의 CSP도 같이 바꿔야 하고, `npm run check`가 둘이 맞는지 봅니다.
- 규격에 맞지 않는 타일은 그리지 않습니다(fail closed). 머리(`version`, `app`, `generated_at`)가 틀리면 그 앱 타일 전체를 뺍니다.
- 보드 위젯 설정(위치, 팀, 시간표)은 이 브라우저에만 저장됩니다. 공개 저장소에 개인 값을 넣지 않습니다.

## 10. 새 타일을 만들 때 체크리스트

1. **톤 고르기**: 표지가 있고 "지금 하는 것"인가? → `sleeve`. 그룹의 주인공인가? → `hero`(그룹에 이미 있으면 쓰지 않음). 최근 N개 표지인가? → `strip`. 장소·도장인가? → `plate`. 지역 진행인가? → `map`. 숫자·목록·한 줄·칸인가? → `type` + `form`.
2. **허용 크기**: 어떤 크기에서 의미가 있는지 정해 `sizes`에 적고, 처음 크기 `size`를 고릅니다.
3. **가장 작은 크기에서도 핵심 한 가지가 읽히는지** 확인합니다.
4. **색**: 새 색을 만들지 않습니다. 표지가 있으면 `accent`를 같이 보냅니다.
5. **글자 위계**: 큰 것 하나 + `--mute` 나머지.
6. **상시 버튼 금지**: 누르면 상세(`detail`) 또는 앱 열기(`href`).
7. **기본으로 보일지**: 보드가 붐비지 않게, 핵심 타일만 `default: true`(생략 시 true), 나머지 후보는 `default: false`로 보내 `+`에서 고르게 합니다.
8. **검증**: 보드에서 다크/라이트, 허용 크기 전부, 휴대폰 폭을 확인합니다.

---

## 11. 하지 않는 것

- 타일마다 테마색을 다르게 주지 않는다.
- `hero`를 같은 그룹에 여러 개 두지 않는다.
- 상시 버튼(편집, 정렬, 필터 칩, 테마 토글)을 늘어놓지 않는다.
- 반경·그림자·테두리 스타일을 타일마다 다르게 하지 않는다.
- 표지 위에 글자를 얹을 때 scrim 없이 올리지 않는다.
- 작은 크기에서 글자를 억지로 줄여 다 보여주려 하지 않는다.
- 외부 폰트를 쓰지 않는다. 외부 이미지와 네트워크는 허용 목록 안에서만.
- 기록이 아닌 것(룰렛 결과 등)을 기록처럼 보여주지 않는다. 룰렛 결과는 '제안'이고, 제안은 Hub 연결이 있을 때만 보낸다.

## 12. 알려진 한계

- 배치 저장이 `localStorage`라서 기기 간 동기화가 되지 않습니다(life-hub P7 B3 이후).
- Life Hub에 연결하기 전에는 앱 타일이 예시 데이터입니다. 연결한 뒤에는 앱이 Hub에 올린 목록만 보이고, 아직 올리지 않은 앱은 보이지 않습니다. 연결이 끊기면(토큰 거부) 예시로 돌아가지 않고 앱 타일을 비웁니다.
- 터치 환경의 길게 누르기·끌기·핸들 크기 조절은 브라우저 에뮬레이션까지만 확인했고 실제 기기에서는 확인하지 못했습니다.
- 날씨(Open-Meteo)와 스포츠(TheSportsDB) 응답 형식은 공개 문서대로 짰지만 이 저장소를 만든 환경에서는 실제 호출을 확인하지 못했습니다. 실패하면 "불러오지 못했어요"로 닫힙니다.
